# Bedrock 测试与验收矩阵

更新：2026-10-28。该矩阵记录证据和缺口，不把编译通过或文件存在等同于游戏功能验收。自动测试位于 `tests/Bedrock.Tests`，使用临时目录和平台替身；CI 配置已增加对应步骤，但本地运行不能证明远端 CI 已通过。

| 要求 | 已有证据 | 尚缺证据 / 限制 |
|---|---|---|
| Windows 安装检测 | 本机当前用户的正式版包被系统 API 找到；测试覆盖未安装、查询失败、未知入口，以及某渠道查询失败时保留另一渠道已完成的结果。 | 未对旧 UWP、Preview、其他设备、系统服务损坏或多账户做真实矩阵。包注册不证明购买。本机只读检查显示正式版已更新到 `1.26.6005.0`，尚未验证该版本的数据布局。 |
| 通过系统启动 | 本机正式版系统激活返回接受；随后观察到游戏进程。页面曾显示请求状态。 | 游戏进程不能证明进入主菜单或授权成功；其他包类型未验证。 |
| Java 保持原功能 | 相对架构基线 `87fea01e3d5066a30be46ec02800de0da5ffa087`，`ModLaunch.vb`、`ModMinecraft.vb` 和 `Settings.vb` 无差异；页面曾能切回 Java。构建产物的公开页面枚举数值及 XAML 导航标签有兼容性检查。 | 尚未在有效 Java 游戏、账户、下载、模组和旧配置上完成真实回归。 |
| `.mcpack` / `.mcaddon` / 文件夹预览 | 测试解析元数据、UUID、版本、范围、依赖，拒绝路径穿越、重复路径、链接、异常压缩和无效清单；覆盖嵌套包、游戏数据内临时目录的拒绝及有限的中英文候选本地化解析。 | 受限解压会拒绝无法归属的文件，兼容性样本仍不足；界面与游戏实际语言回退尚未验证。 |
| 安装及恢复 | 文件夹与压缩包在隔离目录走过准备、事务提交和恢复；测试覆盖冲突、分类路径被文件占用或已安装包布局不明确导致扫描不完整、内容更改、篡改记录、模拟中断及部分成员缺失时的恢复与提示。用户报告本机正式版 `1.26.5203.0` 能在列表中看到自制资源包和行为包；探针安装与恢复完成后核对了文件哈希。 | 尚未完成界面端到端测试；其他版本和设备待验证。当前界面仅对已测游戏包身份开放实验性资源包及行为包路径，不声称游戏已启用包。 |
| 卸载与依赖 | 隔离测试覆盖外部备份、隔离、原位置冲突、世界引用、从隔离内容恢复及从原位置及用户选择的迁移后外部备份恢复（包括篡改、不安全路径和暂存失败）；重复 `pack_id`、无效类型、空 UUID 及 Windows 下配置文件存在写入句柄时，会使世界引用扫描不完整，阻止移除；依赖检查覆盖多个明确目录、版本不匹配、目录类型不符、类型不明确和扫描不完整；跨目录反向 UUID 依赖会阻止移除，扫描不完整也会拒绝；隔离测试覆盖候选全局资源文件引用及无效配置。 | 实验性附加包移除界面与真实用户附加包未验证；世界/依赖检查只覆盖给定目录；反向依赖不区分是否启用或声明版本，可能保守阻止移除；全局配置只检查已知候选路径，缺失不证明无引用，云端和脚本模块也未确认。 |
| 世界备份与恢复 | 隔离世界测试备份、哈希校验、源文件同长度变化及新增目录的拒绝、ZIP 清单与条目大小写不一致的拒绝、损坏拒绝、排除已指定的多个游戏数据根、不覆盖已有备份、与遵循同一根锁的操作串行、恢复为新目录和空目录。 | 源复核不是原子快照，不能排除复核后或复核期间的所有竞争；尚未在真实游戏读取恢复世界，重复内部世界标识和云同步行为未验证。 |
| 世界附加包配置 | 隔离测试覆盖整世界备份、旧内容备份、未知字段保留、过期快照、版本冲突、范围限制、备份恢复、篡改拒绝及替换前并发改动时保留被替换内容；隔离测试覆盖世界配置中的依赖版本、缺失和重复 UUID、反向依赖及配置、声明变化的再检查；实验界面在同一候选根锁范围内备份整个世界并完成复核及修改或恢复，隔离测试覆盖锁等待与备份内容。 | 反向依赖按 UUID 匹配，未检查版本和缺失包；锁不控制游戏和云同步；未验证界面交互、真实游戏格式或云同步。 |
| 配置与文件安全 | 新路径不改 Java 设置文件；相关测试使用损坏或重复输入、禁止目标覆盖、拒绝重解析点。 | 不能证明所有外部进程竞争、突然断电、文件系统故障或所有恶意压缩包都已覆盖；尚无完整旧配置端到端回归。 |
| 历史版本 / 实例 | 已整理官方文档与验证矩阵，见 [04-version-instance-research.md](04-version-instance-research.md)。 | 没有两个经过验证、互不覆盖的版本或实例；P2 未达验收。 |
| 许可证与发布 | 已清点部分直接依赖并记录上游许可历史，见 [05-license-inventory.md](05-license-inventory.md)。 | 外链现行许可正文、修改版分发授权和全部第三方物料仍需核对；没有发布或推送。 |

本地例行命令：

```powershell
dotnet run --project .\tests\Bedrock.Tests\Bedrock.Tests.csproj --configuration Release
dotnet build .\tools\bedrock-probe\PackProbe\PackProbe.csproj --configuration Release
```

WPF 工程使用 Visual Studio MSBuild 构建；如果已有启动器进程占用默认 `bin` 中的 DLL，可使用单独的 `OutDir` 构建，不能把独立输出目录构建当作用户当前运行进程已更新。实机操作必须先确认安装、用户数据根、游戏关闭及同步完成，并保留可恢复记录。
