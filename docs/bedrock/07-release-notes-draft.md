# 发布说明草稿：Bedrock 扩展

**草稿，不是发布许可或完成验收的声明。** 当前有未完成的实机测试、Java 回归和许可核对，不应据此对外发布或宣称所有基岩版功能已支持。

## 当前改动

- 增加独立的 Bedrock 页面，通过当前 Windows 用户已注册的游戏包和系统应用入口发起启动；Windows 接受请求不等于游戏已进入主菜单，授权仍由系统和游戏处理。
- 支持只读预览 `.mcpack`、`.mcaddon` 和已解压包文件夹；可查看 UUID、版本、模块、依赖和资源包使用范围。附加包扫描提供重复 UUID、目录类型及部分依赖提示。
- 增加实验性资源包安装、移除和事务恢复界面；当前写入入口限制为本机验证过的正式版 x64 包 `1.26.5203.0`、`!Game` 入口和 GDK 共享目录。行为包或混合包的图形安装/移除还没有开放。
- 增加世界列表、外部 ZIP 备份、恢复为新目录，以及实验性世界附加包配置入口。世界配置操作先备份整个世界并保留配置副本；当前仅开放给同版本 GDK 用户目录候选。
- 引入隔离的包格式、异常输入、文件事务、备份与恢复自动测试，并在 Windows 构建工作流中加入 Bedrock 测试与验证工具构建。

## 验证范围

- 本机正式版包可向系统提交启动请求，并观察到游戏进程；不能据此证明所有设备或授权状态均可用。
- 用户在本机游戏资源包列表中观察到一个自制测试资源包；游戏关闭并确认同步后，测试包移回暂存，文件哈希与原始测试包一致。事务记录和暂存文件仍保留，未自动删除。
- 本地 Release 自动测试及独立输出目录的 WPF 构建通过；远端 CI 状态和新界面的实际交互尚未验证。

## 仍需完成

- `.mcaddon` 多包、行为包、旧 UWP / Preview 和更多 Windows 环境的实机测试；图形界面安装、卸载与恢复的完整交互测试。
- 使用明确指定的可丢弃世界验证游戏实际读取配置、备份和恢复的行为，以及云同步和重复世界标识的影响。
- Java 版的真实启动、账户、模组、下载和既有配置回归。静态差异显示 Java 启动核心、实例和设置文件未修改，但这不能替代运行测试。
- P2 历史版本及独立实例的合法来源、部署、隔离与恢复验证；P3 原生 Mod 为独立评估项。
- 正式发布前核对上游当前完整许可、修改版分发授权以及全部第三方依赖和资源。详见 [许可清点](05-license-inventory.md) 和 [测试矩阵](06-test-matrix.md)。

世界和附加包操作要求用户确认目标、关闭游戏并等待同步。世界备份为不压缩 ZIP，可能需要接近原始数据大小的空间；失败后可能留下备份、临时目录或事务记录，需要保留并检查。
