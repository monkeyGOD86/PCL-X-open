# Bedrock 实施状态

更新：2026-10-27。本文记录本机验证结果，不能替代其他系统、安装类型或游戏版本的兼容性测试。

## 已实现

- `PCLCS/Bedrock/` 使用 Windows 包查询 API 查找当前用户的正式版和预览版包；读取包版本、架构和系统注册的应用入口，重新验证选择后向 Windows 提交激活请求。账号和授权由系统及游戏处理。包名不用于推断 UWP/GDK；`MicrosoftGame.config` 仅作为 GDK 候选线索。
- WPF 新增独立的基岩版页面，保留旧 `PageType` 数值，并显式映射顶栏按钮。页面展示安装、版本、Gaming Services 注册状态和启动请求结果。安装不存在、查询失败、未知入口和注册变化分别处理。
- `.mcpack` / `.mcaddon` 可通过按钮或从基岩版页面拖放进行只读预览；也可预览解压后的包文件夹。解析 header UUID、版本、类型、依赖、最低引擎版本和资源包使用范围。压缩包检查限制大小、条目数、嵌套、压缩比和路径，并拒绝世界文件、路径穿越、链接、重复路径和无效清单。该预览不写入游戏数据。
- 选定数据目录后可列出本地资源包和行为包，并提示相同 UUID 的重复版本、目录类型不符和可识别的 UUID 依赖缺失或版本不匹配。界面可在发现的候选目录中检查所选包声明的 UUID 和版本；不完整目录会标为无法确认，脚本平台模块及世界中是否启用依赖不作推断。此界面交互尚未实测。
- 资源包实验性安装入口已接入页面：选择并预览文件或文件夹，确认目标、检查范围及游戏关闭后，建立可恢复事务并放置文件。目前仅开放给正式版 Windows 包 `1.26.5203.0` 的 GDK 共享目录；拒绝行为包和混合包。压缩包到界面的端到端交互尚未实测，多包和其他设备兼容性待验证。
- 事务恢复界面可列出选定数据目录中实验性安装事务的路径状态；用户确认游戏关闭与目标后，可以尝试将内容未改变的事务包移回暂存目录。状态仅根据路径判断，恢复时会重新校验内容；界面交互和真实游戏数据恢复尚未实测。
- 实验性的附加包移除记录可在界面列出并尝试恢复到原位置；界面恢复操作要求确认目标与候选目录，并重新校验内容和这些目录内的 UUID 冲突。该入口及真实游戏数据恢复尚未实测。
- 可列出候选基岩版数据目录，用户必须明确选择账户目录后才能查看世界及其配置的资源包、行为包。支持把世界备份到游戏目录之外，重新读取并逐文件校验 SHA-256；也可将校验通过的备份恢复为新的世界目录，不覆盖原世界。备份和恢复前要求用户确认游戏已关闭并检查常见游戏进程。
- `tests/Bedrock.Tests` 是不需要额外测试框架的自动测试程序，CI 针对 PCLCS、测试和子模块变更触发并运行它。

## 本机验证

- Visual Studio 2022 MSBuild Debug 和 Release 构建成功；测试程序覆盖包解析、平台错误、世界元数据以及备份/恢复。备份、恢复及安装事务使用隔离的临时测试目录。
- 当前 Windows 用户的正式版包 `Microsoft.MinecraftUWP_8wekyb3d8bbwe`（包版本 `1.26.5203.0`）通过系统应用入口发起启动，Windows 返回接受请求，随后观察到 `Minecraft.Windows` 进程。
- 实际 WPF 页面显示安装信息；点击启动后显示“Windows 已接受启动请求”，并可返回 Java 启动页面。Java 版游戏本体和登录流程尚未回归。
- 游戏清单声明了 `.mcpack`、`.mcaddon` 文件入口；尚未验证实际导入与回滚。当前机器的 GDK `Users` 下存在共享目录和账户目录，不能仅凭目录存在推断当前游戏账户使用哪个目录。
- `tools/bedrock-probe/PackProbe` 可生成自制测试包并对用户明确选择的目标做只读预检查；真实写入需要用户确认游戏、目录及同步状态并在工具中确认。
- 2026-10-27：经用户确认，对本机正式版 Windows 包 `1.26.5203.0` 的 GDK 共享 `resource_packs` 写入一个自制、独立 UUID 的测试资源包；用户报告在游戏资源包列表中看到了 `PCL Compatibility Test`。用户确认关闭游戏且同步完成后执行事务恢复，检测到新建的资源包目录已移除，测试包移回暂存目录，三个文件的 SHA-256 与原测试包一致。事务记录及暂存文件按设计保留在所选共享数据根下（事务 ID `8dbd428f551c43178961a558ff45fe59`），没有自动删除。此证据仅覆盖一个资源包、一个安装和一次用户观察；不证明 `.mcaddon` 导入、行为包、世界配置、游戏是否启用包、其他系统或旧 UWP 兼容。

## 未完成及门槛

- 行为包和混合包的图形安装、图形卸载以及世界附加包配置尚未实现。实验性后端检查类型、预览内容的 SHA-256 指纹以及提供的目录范围中的重复包，复制到暂存目录后复查并同卷移动，不覆盖现有包；失败时保留暂存目录。`.mcpack` 和包含文件夹或嵌套 `.mcpack` 的 `.mcaddon` 可解压准备；它会拒绝无法确定归属的文件，可能不兼容某些打包格式。多包安装原型先写入并刷新事务记录，暂存全部包，再逐包移动；恢复前核对指纹，只将未修改的包移回事务目录，不删除数据。跨目录冲突检查只覆盖调用方提供的候选目录，无法证明涵盖游戏实际使用的所有目录；准备和提交时必须提供相同范围。旧版事务可以恢复，但不能直接提交。除上文单资源包验证外均待实测，不能将只读预览称为导入成功。任何游戏数据写入前须确认目标安装和数据根，并具备可验证的备份/恢复方案。
- 世界附加包配置编辑后端为实验性原型，尚未接入界面或真实游戏验证。它依据 [Minecraft 清单规范](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/addonsreference/packmanifest) 拒绝向世界启用声明为 `global` 或范围未知的资源包；修改前生成外部备份、检查预览与当前内容的哈希，保留条目的未知字段，并用同目录临时文件替换配置；被替换的文件另行保留。如果修改前配置不存在，恢复时将新配置移至保留文件而非删除。游戏与同步进程必须停止；外部程序仍可能在最后一次检查后并发修改，替换后的保留副本可供人工恢复，不能将此机制视为对其他进程的锁定。
- 附加包移除后端为实验性原型：检查调用方提供的账户世界目录，若存在引用或无法完整检查则拒绝移除；再向用户指定的外部目录复制并校验备份，写入事务记录，将包移动到同卷隔离目录。恢复时不覆盖原位置，并检查内容指纹与 UUID 冲突。世界引用检查只覆盖明确提供且可读取的本地目录，不能证明云端或其他账户没有引用；全局资源配置等其他引用也尚未检查。移除操作尚未接入界面，移除与恢复均未在真实游戏数据上验证。隔离目录和事务记录目前位于游戏数据根内，外部备份由用户指定；这是偏离 `02-architecture.md` 建议的事务存储位置的实现，需要进一步评估和迁移方案。
- 世界恢复在目标数据根下建立临时目录，校验完成后同卷移动到新世界目录；进程中断可能留下 `.pcl-restore-*` 临时目录，不会自动删除。常见进程检查和用户确认无法证明云同步完成或覆盖所有游戏进程；当前未在真实游戏存档上测试备份或恢复，也未验证游戏能否读取恢复的新世界。
- Minecraft 官方文档将 GDK [共享创作者内容目录](https://learn.microsoft.com/en-us/minecraft/creator/documents/gdkpcprojectfolder) 与 [按用户保存的世界目录](https://github.com/MicrosoftDocs/minecraft-creator/blob/main/creator/Documents/BedrockServer/getting-started.md) 区分；共享目录不得作为世界恢复目标。具体用户目录仍需用户确认。
- UWP 旧版本、Preview、未安装/授权失败、服务损坏及多种 Windows 环境尚未做真实设备验证。`App` 入口依据历史包惯例识别，兼容性尚未实测。
- 历史版本、多实例和原生 Mod 仍属独立验证项；证据、限制及验证矩阵见 [04-version-instance-research.md](04-version-instance-research.md)。许可风险及本次直接依赖的清点见 [05-license-inventory.md](05-license-inventory.md)；当前上游许可全文和完整第三方物料仍需在发布前核对。
