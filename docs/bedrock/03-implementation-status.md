# Bedrock 实施状态

更新：2026-10-27。本文记录本机验证结果，不能替代其他系统、安装类型或游戏版本的兼容性测试。

## 已实现

- `PCLCS/Bedrock/` 使用 Windows 包查询 API 查找当前用户的正式版和预览版包；读取包版本、架构和系统注册的应用入口，重新验证选择后向 Windows 提交激活请求。账号和授权由系统及游戏处理。包名不用于推断 UWP/GDK；`MicrosoftGame.config` 仅作为 GDK 候选线索。
- WPF 新增独立的基岩版页面，保留旧 `PageType` 数值，并显式映射顶栏按钮。页面展示安装、版本、Gaming Services 注册状态和启动请求结果。安装不存在、查询失败、未知入口和注册变化分别处理。
- `.mcpack` / `.mcaddon` 可通过按钮或从基岩版页面拖放进行只读预览；也可预览解压后的包文件夹。解析 header UUID、版本、类型、依赖和最低引擎版本。压缩包检查限制大小、条目数、嵌套、压缩比和路径，并拒绝世界文件、路径穿越、链接、重复路径和无效清单。该预览不写入游戏数据。
- 选定数据目录后可列出本地资源包和行为包，并提示相同 UUID 的重复版本、目录类型不符和可识别的 UUID 依赖缺失或版本不匹配。脚本模块依赖和跨目录的依赖仍需进一步验证。
- 事务恢复界面可列出选定数据目录中实验性安装事务的路径状态；用户确认游戏关闭与目标后，可以尝试将内容未改变的事务包移回暂存目录。状态仅根据路径判断，恢复时会重新校验内容；界面交互和真实游戏数据恢复尚未实测。
- 可列出候选基岩版数据目录，用户必须明确选择账户目录后才能查看世界及其配置的资源包、行为包。支持把世界备份到游戏目录之外，重新读取并逐文件校验 SHA-256；也可将校验通过的备份恢复为新的世界目录，不覆盖原世界。备份和恢复前要求用户确认游戏已关闭并检查常见游戏进程。
- `tests/Bedrock.Tests` 是不需要额外测试框架的自动测试程序，CI 针对 PCLCS、测试和子模块变更触发并运行它。

## 本机验证

- Visual Studio 2022 MSBuild Debug 和 Release 构建成功；测试程序覆盖包解析、平台错误、世界元数据以及备份/恢复。备份、恢复及安装事务使用隔离的临时测试目录。
- 当前 Windows 用户的正式版包 `Microsoft.MinecraftUWP_8wekyb3d8bbwe`（包版本 `1.26.5203.0`）通过系统应用入口发起启动，Windows 返回接受请求，随后观察到 `Minecraft.Windows` 进程。
- 实际 WPF 页面显示安装信息；点击启动后显示“Windows 已接受启动请求”，并可返回 Java 启动页面。Java 版游戏本体和登录流程尚未回归。
- 游戏清单声明了 `.mcpack`、`.mcaddon` 文件入口；尚未验证实际导入与回滚。当前机器的 GDK `Users` 下存在共享目录和账户目录，不能仅凭目录存在推断当前游戏账户使用哪个目录。

## 未完成及门槛

- 附加包图形界面导入、安装/卸载和世界附加包配置尚未实现。实验性后端只在隔离目录测试：检查类型、预览内容的 SHA-256 指纹以及所选目录中的重复包，复制到暂存目录后复查并同卷移动，不覆盖现有包；失败时保留暂存目录。`.mcpack` 和包含文件夹或嵌套 `.mcpack` 的 `.mcaddon` 可解压准备；它会拒绝无法确定归属的文件，可能不兼容某些打包格式。多包安装原型先写入并刷新事务记录，暂存全部包，再逐包移动；恢复前核对指纹，只将未修改的包移回事务目录，不删除数据。上述安装流程未接入界面，也未验证真实游戏识别；跨目录冲突检查尚未完成，不能作为已支持的安装功能。冲突检查限于所选数据目录中的本地包；不能将只读预览称为导入成功。任何游戏数据写入前须确认目标安装和数据根，并具备可验证的备份/恢复方案。
- 世界恢复在目标数据根下建立临时目录，校验完成后同卷移动到新世界目录；进程中断可能留下 `.pcl-restore-*` 临时目录，不会自动删除。常见进程检查和用户确认无法证明云同步完成或覆盖所有游戏进程；当前未在真实游戏存档上测试备份或恢复，也未验证游戏能否读取恢复的新世界。
- Minecraft 官方文档将 GDK [共享创作者内容目录](https://learn.microsoft.com/en-us/minecraft/creator/documents/gdkpcprojectfolder) 与 [按用户保存的世界目录](https://github.com/MicrosoftDocs/minecraft-creator/blob/main/creator/Documents/BedrockServer/getting-started.md) 区分；共享目录不得作为世界恢复目标。具体用户目录仍需用户确认。
- UWP 旧版本、Preview、未安装/授权失败、服务损坏及多种 Windows 环境尚未做真实设备验证。`App` 入口依据历史包惯例识别，兼容性尚未实测。
- 历史版本、多实例和原生 Mod 仍属独立验证项。许可证全文及依赖许可仍需在发布前核对。
